# ScriptChecker 設計書

日付: 2026-10-30 / 状態: Human承認済み(ルビ表示の方針を反映)

## 1. 目的(なぜ作るか)

Script2Video の `build` で作った `full_dialogue.wav` を、ルビ振り済み台本を見ながら聞いて確認するための補助ツール。主な確認対象は「音声レベル」と「誤読・ルビ(読み指定)の誤り」。YouTube番組(AI道具箱など)の制作で、公開前チェックの時間を減らすのが狙い。

## 2. ゴール / ノンゴール

**ゴール**
- 台本(`第N回.txt`)を指定すると、同じフォルダの `full_dialogue.wav` と `timeline/timeline.json` を自動で読み込む。
- 音声再生に同期して、台本の該当行を強調表示する。可能な範囲で文字単位まで追跡する。
- スペアナⅡ流のレベルメーターを表示する。
- 6操作(早戻し再生/10秒戻し/停止/通常再生/10秒送り/早送り再生)と、現在位置のシークバーを備える。
- 台本表示エリアを最大限広く取る。

**ノンゴール**
- 台本・音声・タイムラインの編集、再ビルド。
- 動画・BGM・SE・字幕出力の確認(対象は `full_dialogue.wav` のみ)。
- スペアナ、スペクトログラム、ベクトルスコープなど、メーター以外の解析表示。
- スペアナⅡ本体の変更。

**アンチゴール(技術的に動いても失敗)**
- 強調行が実際の音声とずれて見えること(確認ツールが誤誘導になる)。
- 台本が狭く窓の大半をメーターが占めること。

## 3. 入力(確認済みの事実)

対象例: `D:\UDS\YouTube\AI道具箱\第60回`

| ファイル | 用途 |
|---|---|
| `第60回.txt` | 台本。`[S01-L001] 蒼真:台詞` の行と `#paragraph[S01] 見出し` を含む。台詞中の `'単語\|読み'` が読み指定(表示は「単語」、発声は「読み」)。 |
| `timeline/timeline.json` | 全行の `id`, `scene`, `cast`, `text`(表示文), `start_ms`, `end_ms`。`script_sha256` も持つ。行の強調はこの時刻で正確にできる。 |
| `full_dialogue.wav` | 約936秒、48kHz、WAVE_FORMAT_EXTENSIBLE(約270MB)。Python標準`wave`では開けないため、Rustの`hound`等で読む。 |

台本→`timeline.json` の行対応は行ID(`S01-L001`)で取る。ID不一致・`missing: true` の行は警告表示にとどめ、クラッシュしない。

## 4. 画面(1ウィンドウ・3パネル構成)

「窓」は、1つのアプリウィンドウ内の3パネルとして実装する(私の判断)。

```
┌───────────────────────────────┬──────┐
│                               │メーター│
│        台本表示エリア(広い)        │(細く  │
│                               │ 密着) │
├───────────────────────────────┴──────┤
│ [⏪][⏴10s][■][▶][10s⏵][⏩]            │
│ 00:12.3 ───●──────────────── 15:36.7 │
└──────────────────────────────────────┘
```

- **台本表示エリア**: 画面の大半。シーン見出し(`S01 オープニング`)で区切り、行ごとに `話者: 台詞` を表示。読み指定のある語は、語の上に読みを小さなルビ文字で併記する(読みの確認が目的のため。Humanの指示)。ルビは egui 標準では描けないため、語単位のカスタム描画で実装する。ルビ表示のON/OFF切替も付ける。再生中の行を背景色で強調し、自動スクロールで追従する(追従のON/OFF切替あり)。行をクリックするとその行頭へシークする。
- **メーター**: 右端に細く配置。チャンネルバー同士を密着させ、レベルが読める最小限の幅にする。スペアナⅡの `meter_view.rs` / `meter.rs` を参考にし、RMS・ピーク・ピークホールドを表示する(目盛 -60〜0 dBFS)。
- **操作パネル**: 下部。6ボタンの列と、その下に現在位置のシークバー(ドラッグでシーク、現在時刻/総時間表示)。

## 5. 再生動作

- **通常再生/停止**: 停止は位置を保持する。
- **10秒戻し/10秒送り**: 再生中でも停止中でも、位置を±10秒(0〜総時間にクランプ)。
- **早送り再生/早戻し再生**: 押している間ではなく、押すとその方向の高速再生に入り、通常再生または停止で解除。倍率は4倍(私の判断。後で変更可能な定数にする)。早戻しは音声を逆方向に再生する(テープの巻き戻し式)。
- 再生位置はデバイス非依存のフレーム位置を正本にして、台本強調・メーター・シークバーが同じ位置を参照する(スペアナⅡの`PlaybackClock`の考え方を引用)。
- 表示・停止・シークの基準は、出力レイテンシを補償した**可聴位置**とする。通常再生・早送りでは現在の再生区間の開始可聴位置より手前へ戻らず、早戻しでは開始可聴位置より先へ進まない。モード切替、シーク、skipでは開始可聴位置を更新し、切替直後に表示位置を跳ばさない。
- 出力は `cpal`。270MBの全読み込みは許容(メモリ約360MB/f32)。

## 6. 文字単位の追跡(推定)

`timeline.json` には行内の文字時刻がない。行の `start_ms`〜`end_ms` を、**読みに基づく重み**で文字に割り振る推定とする。

- 読み指定のある語は、読み(かな)のモーラ数を重みにし、表示文字には読みの範囲全体を割り当てる。
- 読み指定のない語は、かな=1モーラ、漢字=2モーラ相当、英数字=0.5(私の初期値)で重み付け。
- 句読点(、。)は無音の重みを持たせる(一定の割合で停止時間とみなす)。

推定のため、精度は行内で数百ms程度のずれを許容する。ずれが大きい場合の次の手段として、将来VOICEVOXのモーラ時間を取得する案があるが、今回は対象外。強調は「行レベルは正確、文字レベルは目安」と画面上で区別する(行強調は背景色、文字追跡は文字色/下線)。

## 7. 異常系

- `full_dialogue.wav` または `timeline.json` が無い場合は、具体的なパスを示すエラー表示。
- 台本ファイルの SHA-256 が `timeline.json` の `script_sha256` と違う場合、「台本がbuild後に変更されています。強調位置がずれる可能性があります」と警告(再生は許可)。
- 音声の長さと `duration_ms` が大きく違う場合も警告。
- 出力デバイス異常は再生を止めて理由を表示。

## 8. 技術方針(私の判断)

- Rust 2024 / `eframe 0.31`(スペアナⅡと同スタック)。`D:\UDS\宇摩コードワークス\ScriptChecker\` に独立プロジェクトとして作る。
- スペアナⅡの`meter.rs`/`meter_view.rs`の必要部分は、**パス依存ではなくコピーして引用**する。他プロジェクトの未整理(dirty)なツリーに依存させず、スペアナⅡ側を一切変更しないため。
- JSON解析は `serde_json`、WAVは `hound`、ファイル選択は `rfd`、ハッシュは `sha2`。
- 台本パーサ、時刻→行/文字の変換、再生位置計算は、UIと分離した純ロジックにし、単体テストする。実機の第60回データでの動作確認を完了条件に含む。
- Git管理し、工程は Beads(`bd`)で管理する(Humanの指示)。運用は D:\UDS 共通規程に従う(実装後に独立レビュー、push は別途Human承認)。

## 9. 完了条件

1. 第60回の台本を指定して全6操作とシークバーが動く。
2. 再生中、行強調が `timeline.json` の時刻どおりに切り替わる(複数箇所を耳と目で確認)。
3. メーターが表示され、台本エリアが画面の過半を占める。
4. 欠損ファイル・台本不一致の警告が出る。
5. 単体テストが通る。
